Ask business questions.
Get answers from your live data.

A Python service that connects Claude, GPT, Grok, and Gemini to a live Odoo instance. The model asks Odoo questions itself — schema lookup, read_group totals, filtered searches — then answers only from what came back. In English, Roman Urdu, or Urdu.

CAPABILITIES

What the service does

🧠
Multi-model routing with fail-over

Selects the right model for the question — fast / smart / deep tier, or auto — and falls over to the next configured provider if one fails. No vendor lock-in.

ClaudeGPT GrokGroq Gemini
🔌
Odoo tool calls — not text dumps

The model doesn't receive a pre-stuffed text dump of rows. It calls odoo_metric, odoo_aggregate, odoo_search_read itself, and answers only from what came back.

read_groupsearch_read fields_get
📊
Verified KPI semantic layer

Sales, receivables, payables, CRM pipeline, stock, headcount — each has one pinned definition (model, states, date field). The model calls the metric, not improvised domains.

metrics.jsonoverride
🌍
Urdu / Roman Urdu / English

Questions in any of these three are answered in the same language. Business vocabulary (bikri, udhaar, wasooli, kharcha) is mapped to metric keys in the system prompt.

اردوRoman Urdu
⚡
Async, cached, horizontally scalable

Shared httpx pool, per-host concurrency cap, uid / schema / data cached in memory or Redis. Stateless — add replicas freely. Rate-limited per user.

Redishttpx asyncio
📋
Audit log + accuracy evals

Every question, tool call (with args) and answer is logged to JSONL. Golden-set evals compute expected totals from Odoo directly and diff against the model's answer.

SEMANTIC LAYER

Verified KPI catalogue

Each metric pins down one business definition so the answer to "is mahine ki bikri kitni thi?" is always computed the same way. Extend via knowledge/metrics.json.

sales_total

Confirmed orders (state=sale/done), amount_total, by date_order

Receivables whose invoice_date_due < today (point-in-time)
payables_open
Payables outstanding
Vendor bills not fully paid, shown as positive number
crm_pipeline_open
Open CRM pipeline
Active opportunities (probability < 100), expected_revenue
DEPLOYMENT

Run it in under five minutes

  1. 1
    Clone and install

    cd ai-service && pip install -r requirements.txt. Python 3.11+ required.

  2. 2
    Fill .env

    Set ODOO_URL, ODOO_DB, ODOO_USERNAME, ODOO_API_KEY (Odoo → Settings → Users → API Keys), and at least one LLM key.

  3. 3
    Start the server

    uvicorn app.main:app --reload --port 8000. Docker with Redis: docker compose up --build.

  4. 4
    Connect the dashboard

    Dashboard → Settings → AI Assistant → Provider DashView AI → paste the backend URL. No key reaches the browser.

  5. 5
    Run tests (no keys needed)

    pip install -r requirements-dev.txt && pytest -q 

# .env — minimal config
ODOO_URL=https://yourcompany.odoo.com
ODOO_DB=yourcompany-live
ODOO_USERNAME=dashboard@company.com
ODOO_API_KEY=abc123...

ANTHROPIC_API_KEY=sk-ant-...

# Optional: server-side read-only credentials

# Verify Odoo connection

  -H "Authorization: Bearer $JWT"
SECURITY & SAFETY

Guardrails baked in, not bolted on

🔒
Read-only by construction

Only search_read / search_count / read / read_group / fields_get can be sent. The guard rejects any other method before the RPC call is even made.

🚫
Security models blocked

res.users, ir.*, payment.*, mail.mail and more are blocked by prefix. Secret-looking field names are hidden from results.

✅
Domain / groupby / order validation

Every domain term, field path, measure, and order clause is validated against strict regex before reaching Odoo. Prompt injection via field values is structurally impossible.

🌐
SSRF guard on client credentials

Browser-supplied Odoo URLs are DNS-resolved before use. Private / loopback / link-local addresses are refused. ODOO_ALLOWED_HOSTS pins to an explicit list in production.
