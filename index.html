how it works

Five steps, one review.

DashView doesn't skip straight to a diff. It plans out loud first, so what lands in your review queue is something you already agreed to.

01

Describe the ticket

Paste a Jira ticket, a Linear issue, or a plain-English request. No special syntax required.

> "Add a sliding-window rate limiter to the public API"
02

Review the plan

DashView reads the repo, checks existing patterns, and drafts a step-by-step plan before writing a line of code.

1. Add rateLimiter.ts (Redis-backed)
2. Wire into route middleware
3. Add config + env defaults
4. Write unit + integration tests
03

Code gets written

Following your repo's existing conventions — not generic boilerplate pulled from nowhere.

+ export function rateLimiter(opts: Opts) {
+ return slidingWindow(opts.redis, opts.max)
+ }
- // TODO: add rate limiting
04

Tests run automatically

Existing suites run first; new tests are written for the exact change. Nothing opens on red CI.

With commit-level history, a written summary, and a link to the live run — ready for a human to approve.

frequently asked

Questions engineering leads actually ask.

Can it merge code without a human?+

No. DashView opens pull requests and respects your existing branch protection rules — a reviewer always has to approve before anything reaches your default branch.

What happens if a task is ambiguous?+

DashView stops at the planning step and asks a clarifying question instead of guessing. You'll never see a PR for a task it wasn't confident about.

Does it work with our existing test suite?+

Yes — it runs your existing tests first and writes new ones in the same framework and style already used in your repo.

Can we self-host it?+

Enterprise plans support self-hosted and VPC deployments, so code never has to leave your own infrastructure.

Is it really free for a growing team?+

Yes — DashView has no per-seat billing and no subscription. Every repo you connect gets the full feature set, whether you're a team of 3 or 300.

What languages and frameworks are supported?+

DashView reads whatever conventions already exist in your repo, so it isn't limited to a fixed language list — support is broadest for common backend and frontend stacks.
